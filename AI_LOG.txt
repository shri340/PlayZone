1. PROJECT OVERVIEW
-------------------
PlayZone is a Java-based sports equipment rental management project created for
a hackathon/demo. It was extended into a locally hosted web application so that
the rental system and its additional features can be demonstrated through a
browser.

Main goals:
- Manage sports equipment inventory.
- Create rentals and calculate bills.
- Apply borrower-type discounts and GST.
- Validate equipment availability and handle invalid requests safely.
- Maintain rental history and reports.
- Provide useful decision-support and social matchmaking features.
- Run locally from VS Code without requiring an external database or framework.

2. TECHNOLOGY AND ARCHITECTURE
------------------------------
Backend:
- Java
- Java's built-in com.sun.net.httpserver.HttpServer
- Lightweight JSON request/response handling
- In-memory arrays for demo data and session state

Frontend:
- HTML
- CSS
- Vanilla JavaScript
- Fetch API calls to the local Java backend

Runtime:
- Default server port: 8080
- Local browser URL: http://localhost:8080
- Optional custom port: -Dplayzone.port=8091

No external database or third-party Java web framework is required by this
local demo version. In-memory rental, lobby and profile data resets when the
server process is restarted.

Billing rules in the web version:

- Student discount: 10%
- Staff discount: 15%

Inventory safety:
- Requested quantities are validated before stock is changed.
- Rental line items and the rental object are created before committing stock

D. Smart Stock Guardian / Smart Insights
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
A Smart Insights page was added to the website.

Purpose:
Provide transparent stock and demand information using the rental activity
recorded in the current server session.

Implemented calculations:
- Total rental transactions
- Quantity rented for each equipment type
- Rental frequency per equipment type
- Relative demand score
- Low-stock and critical-stock indicators
- Suggested restock quantity relative to the starting stock
- Identification of the current demand leader

Risk labels:
- CRITICAL: 3 or fewer units available
- WATCH: fewer than 10 units available
- HEALTHY: 10 or more units available

The insights are rule-based calculations over actual in-session rental records.
They are NOT a trained machine-learning model and should not be described as
AI forecasting.

E. Reality Rift — scenario simulator
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
A feature named Reality Rift was added as a scenario-planning simulator.

Available example scenarios:
- Calm Campus
- Tournament Surge
- Monsoon Flip

User controls include:
- Participant count
- Chaos/demand multiplier
- Option to include an unsaved rental draft in the scenario

The simulator reads current equipment availability and estimates:
- Projected demand
- Stock that can be served
- Potential shortages
- Coverage score
- Suggested counter-move / rescue plan

Reality Rift is a deterministic, illustrative scenario simulator. It does not
reserve or deduct actual inventory. Its demand profiles are predefined
assumptions, not live event data and not machine-learning predictions.

F. GameBond — campus multiplayer matchmaking and cost sharing
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
GameBond was added as a social feature to help people find others to play
multiplayer or group games with and share estimated expenses.

Supported games:
- Chess
- Carrom
- Badminton
- Football
- Basketball
- Table Tennis
- Volleyball
- Cricket

Player profile preferences:
- Nickname
- Game
- Skill level (Beginner, Intermediate, Advanced)
- Preferred time (Morning, Afternoon, Evening)
- Maximum per-person budget

Create-group fields:
- Game
- Skill level
- Time slot
- Player capacity
- Estimated total expense

Matching logic:
- The selected game must match.
- Same preferred time adds compatibility points.
- Skill similarity adds compatibility points.
- A group is excluded if the estimated share exceeds the player's budget.
- Full groups and groups already containing the searching nickname are excluded.
- Matches are sorted by compatibility score.

Compatibility is a transparent, deterministic rule-based score. It is not an
AI-trained recommendation model.

Joining a group:
- Adds the nickname to the group's member list.
- Updates the player count.
- Recalculates the estimated per-person share using total estimated cost divided
  by the updated number of players.

Safety and prototype limitations:
- Nicknames only; no phone numbers, email addresses or precise location.
- No chat, payments, real-time notifications or identity verification.
- Groups are held in memory and reset when the server restarts.
- The expense share is an estimate, not a payment request or transaction.
- Players should confirm venue, availability and final expense before meeting.

G. GameBond — 50 fictional demo member profiles
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The latest update added 50 synthetic GameBond member profiles. The profiles are
automatically seeded when the Java server starts.

Each fictional profile contains:
- Nickname (CampusPlayer01 through CampusPlayer50)
- Preferred game
- Skill level
- Preferred time slot
- Per-person budget
- demo=true marker in the member API response

Each of the 50 profiles also hosts one open demo game circle. This makes the
GameBond discovery area populated immediately for a hackathon presentation and
allows the matching algorithm to be demonstrated without manually creating
the first groups.

The profiles are fictional demonstration records. They are not real students,
not scraped from a campus directory, and not collected personal information.
The same deterministic sample set is recreated at server startup.

New API:
- GET /api/gamebond/members — returns the 50 demo member profiles.

Existing GameBond APIs:
- GET /api/gamebond/lobbies — returns open game circles.
- POST /api/gamebond/lobbies — creates a game circle.
- POST /api/gamebond/recommend — finds compatible groups.
- POST /api/gamebond/join — joins a group.

7. HOW TO RUN THE PROJECT
-------------------------
Open the extracted PlayZone_Web folder in VS Code.

From PowerShell in the project root:

    javac -encoding UTF-8 -d out src/playzone/Main.java src/playzone/model/*.java src/playzone/people/*.java src/playzone/exceptions/*.java src/playzone/service/*.java src/playzone/web/*.java

    java -cp out playzone.web.PlayZoneWebServer

Then open:

    http://localhost:8080

Keep the terminal running while using the website.

To use a different port:

    java -Dplayzone.port=8091 -cp out playzone.web.PlayZoneWebServer

Then open http://localhost:8091.

9. CURRENT LIMITATIONS / HONEST DEMO DESCRIPTION
------------------------------------------------
- This is a local prototype, not a production campus platform.
- Data is stored in memory; server restart resets rentals and GameBond groups.
- The 50 GameBond profiles are synthetic sample data.
- GameBond matching and Smart Insights are rule-based, not trained AI.
- Reality Rift uses illustrative scenario assumptions.
- No real payment gateway, chat, push notifications, account login, identity
  verification or live location service is implemented.
- Do not present synthetic members as actual enrolled students.
- Do not claim that the prototype uses machine learning unless a real trained
  model is added and integrated.
